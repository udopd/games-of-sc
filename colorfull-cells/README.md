# Colorfull Cells

Многопользовательская песочница для SUPER CUBE. Поле 100 × 100, восемь постоянных пешек, палитра, ластик и цветные бомбы. Без npm-зависимостей и CDN; Node.js 22+.

## Запуск

В PowerShell из папки проекта:

```powershell
npm start
```

Открыть http://localhost:1212 в нескольких вкладках или на устройствах одной сети по адресу компьютера. Для другого порта: `$env:PORT='3317'; npm start`. Двойной клик по index.html не запускает игровой сервер.

Для постоянно работающего сервера с автоматическим перезапуском и постоянным томом:

```powershell
docker compose up -d --build
```

Открыть http://localhost:1212. Docker должен работать, компьютер/хост должен оставаться включённым. Для доступа через интернет потребуется размещение сервера с HTTPS и обратным прокси; публикация не выполнялась.

## Правила

- Стрелки / WASD (также ФЦЫВ), экранные стрелки, свайпы или касание соседней клетки: строго один шаг по горизонтали/вертикали. Занятые пешками клетки блокируют движение.
- Цвета 1–8 или палитра; пробел/кнопка красит текущую клетку, E/У/ластик стирает. Ход сам по себе не красит.
- Бомбы появляются каждые 2,5 секунды, максимум 40. При наступании красят круг `dx² + dy² ≤ 25`, включая центр; пешки не погибают. Цепных взрывов нет.
- Сервер всегда держит восемь пешек. Вход забирает свободную пешку бота без телепортации. Выход немедленно освобождает её; аварийное отключение — через 10 секунд без запросов. Девятый игрок ждёт свободное место.
- Мир живёт на сервере даже без вкладок. При выключенном сервере симуляция остановлена; офлайн-время не симулируется задним числом.
- Счётчик пешки учитывает операции покраски, включая действия её бота и повторную покраску. Это совместная песочница без победителя и личного рейтинга.

## Архитектура и сохранение

`server/world.js` — независимые правила; `server/index.js` — HTTP, токены сессий, проверка действий, жизнь ботов, атомарные снимки. Клиент получает общее состояние по постоянному потоку, с HTTP-восстановлением при сбоях. Токены остаются в памяти вкладки; данные чужих сессий не выдаются. Команды имеют последовательные номера и ограничение частоты. Один серверный процесс на мир; горизонтальное масштабирование не реализовано.

Мир записывается каждые пять секунд и при штатной остановке в `data/world.json` (схема v1). `DATA_DIR` меняет каталог. При перезапуске все пешки становятся ботами. Повреждённый/неизвестный снимок заменяется новым миром. Аварийная остановка может потерять последние пять секунд.

В существующем runtime SUPER CUBE `/app` только для чтения; игра использует `/tmp/colorfull-cells`, если основной каталог недоступен. **Для сохранности мира при пересоздании контейнера платформа должна монтировать отдельный writable volume и передавать DATA_DIR.** Встроенный compose уже делает это. Код платформы этим проектом не изменяется.

`assets/platform.js` изолирует публичный SDK. Текущий getUser возвращает authenticated/displayName/playerId. Облако хранит только цвет и звук (v1), общее поле всегда серверное. Запись разрешается только после успешного чтения валидного/пустого облачного сохранения; записи идут последовательно. Чужая/неизвестная схема не перезаписывается. Кнопка синхронизации повторяет подключение. Состояние избранного берётся из подтверждённого результата SDK или настроек родителя, не переключается при чтении.

Настройки `SC_PLATFORM_SETTINGS` принимаются только от window.parent с проверкой типов. RU/EN и светлая/тёмная тема меняются без сброса мира. SDK не обязателен; при отсутствии работает гость. Игра не доверяет клиентскому имени как доказательству платформенной идентичности. В серверных сессиях все игроки используют случайные гостевые токены, отдельного входа нет.

## Проверка

```powershell
npm test
```

Проверки правил и настоящего HTTP-сервера: движение, границы, занятые клетки, раскраска/ластик, радиус взрыва, восемь мест, общее состояние, запрет повторной команды, замена ботом и восстановление снимка. Подробности фактической проверки в VALIDATION.md.

## Платформа

`runtime.txt=server`, вход — `server/index.js`, порт по умолчанию 1212, адрес 0.0.0.0. Все клиентские пути относительные, включая API для `/server-games/<slug>/`. Для загрузочного ZIP нужны файлы проекта в корне, без data и тестового мира. Текстовые метаданные включены; обложка 630×500 включена в media/capsule.jpg; каталоговые скриншоты не подготовлены, готовый ZIP не заявляется.

Исходная графика пешек рисуется кодом; внешние изображения, шрифты и аудиозаписи не используются. Звук синтезируется Web Audio после пользовательского действия, поддерживается reduced motion.

Локальный порт по умолчанию: 1212. Для runtime SUPER CUBE, ожидающего порт 3000, передайте PORT=3000 в окружении контейнера. Интерфейс занимает высоту окна без прокрутки; шапка и вводный блок удалены, служебные кнопки перенесены к палитре.


Исправление подключения: игровые сессии передаются в JSON-теле POST-запросов. Это совместимо с прокси SUPER CUBE, который удаляет Authorization. Для простого запуска используйте Start-Game.cmd и откройте http://localhost:1212; оставьте окно сервера открытым.


Docker использует внутренний порт 3000 (контракт SUPER CUBE); compose публикует его как localhost:1212. Обычный npm start по умолчанию слушает 1212.


## Защищённые области и мини-карта

Нажмите «Оградить», затем укажите два угла прямоугольника на поле (мышью или двумя касаниями). Первый и второй углы включаются в область. При выборе видны предварительные границы и число клеток. Повторное нажатие «Отмена» или Escape отменяет выбор. Движение на время выбора приостановлено. Масштаб можно уменьшить, чтобы выделить большую область.

Каждая из восьми пешек имеет собственный общий лимит 256 клеток. Можно поставить несколько отдельных прямоугольных заборов. Области не пересекаются, в том числе с другими областями того же владельца. Сервер проверяет лимит и пересечения атомарно; недопустимая область не устанавливается частично.

Никто не может красить и стирать защищённые клетки: ни владелец, ни другие игроки, ни боты. Бомбы пропускают защищённые клетки; новые бомбы внутри них не появляются. Проход пешек остаётся свободным. Цвет заборов следует текущему цвету их пешки. Чтобы снять отдельный забор, встаньте внутри своей области и нажмите «Снять забор». Её клетки снова доступны для изменений, а лимит освобождается.

Области принадлежат постоянным восьми пешкам. При выходе игрока они остаются за его пешкой-ботом, а новый игрок, получивший эту пешку, наследует её области и возможность снять заборы. Боты сами не устанавливают и не снимают заборы. Это соответствует существующей модели передачи пешек, отдельного владения аккаунтами нет.

Мини-карта в левом верхнем углу показывает всё поле, цветные защищённые области и восемь пешек. Ваша пешка выделена белой точкой и более толстой обводкой; пунктир отмечает область камеры.

Снимок мира теперь имеет версию 2 и содержит regions. Снимки v1 автоматически восстанавливаются без заборов; краска и положения пешек сохраняются. При загрузке областей повторно проверяются координаты, пересечения и индивидуальные лимиты.

## Управление и эффекты

Пробел или F — покраска, E — ластик. 1–8 (верхний ряд и цифровой блок) выбирают цвет, Q/R и квадратные скобки переключают предыдущий/следующий цвет циклически. Физические клавиши работают в русской раскладке. Клавиши заблокированы в меню, просмотре карты и при выборе забора; пробел после клика по палитре красит клетку. Номера подписаны на цветах.

Успешная покраска передаётся сервером как событие всем игрокам и создаёт 28 квадратных частиц. Бомба создаёт 360 частиц, расширяющееся кольцо и затухающую тряску игрового поля до 600 мс. Дальние взрывы не трясут камеру. Общий предел — 1800 живых частиц; они исчезают через короткое время. При prefers-reduced-motion тряска отключена, частиц меньше. События не являются игровыми данными и не сохраняются в файл мира.

Мини-карта расположена под кнопками забора. Нажатие открывает модальный просмотр всего мира с нумерованными пешками, цветами, бомбами и областями. Колёсико и кнопки меняют масштаб от 100 до 1200 процентов, перетаскивание мышью/пальцем перемещает карту. «Всё поле» возвращает полный обзор; Escape и крестик закрывают карту. Управление пешкой в это время отключено, мир продолжает жить. Рейтинг цветов доступен и в этом окне, в том числе на коротких экранах.

Рейтинг отсортирован по количеству клеток каждого из восьми цветов. Процент всегда считается от всех 10000 клеток; стирание уменьшает долю цвета. Показатель рядом с заголовком — общая заполненность. Это рейтинг цветов, а не личные очки игроков.

В игре нет кнопок смены темы/языка: они приходят от платформы. Светлая тема остаётся нежно-зелёной; тёмная использует графитовые и тёмно-синие панели с контрастными цветами.

## Присутствие игроков

После входа клиент поддерживает поток POST /api/presence. При нормальном разрыве соединения сервер сразу передаёт пешку боту. Кнопка выхода, закрытие страницы и скрытие вкладки также освобождают её; скрытая вкладка возвращается как новый участник при активации. Одновременные входы одной вкладки предотвращены. При потере сети без сигнала закрытия резервная проверка освобождает сессию через 10 секунд без запросов (с точностью серверного тика 650 мс). Абсолютно мгновенно определить сетевой обрыв невозможно. После ручного выхода доступно живое наблюдение за миром без занятого места.

Обратный прокси должен передавать поток presence без буферизации. Игра отправляет X-Accel-Buffering: no и регулярные heartbeat; поведение реального production-прокси не проверялось.

## Покраска при движении
Удерживайте пробел и перемещайтесь стрелками/WASD: каждая новая клетка автоматически красится выбранным цветом. Шаг и покраска обрабатываются сервером одной командой. После отпускания пробела, потери фокуса, открытия меню/карты/режима ограждения или выхода режим сбрасывается. Защищённые клетки не меняются, проход через них сохраняется. Неуспешный шаг ничего не красит. На клетке с бомбой сначала срабатывает взрыв, затем кисть красит только клетку под пешкой.


## Сборка ZIP
Выполните из папки игры: .\Package-Game.ps1
Архив появится в соседней папке _builds под именем Colorfull_Cells.zip. Если файл уже существует, новый архив получает дату в имени. В ZIP есть index.html и runtime.txt в корне, исходники, media с капсулой и тесты. Папка data, сохранения мира и журналы исключены. Сервер игры при сборке не запускается; скрипт может читать исходники и при работающем сервере.


## Расположение управления
Палитра находится в левой колонке панели управления, стрелки перемещения — в правой и больше не закрывают поле. Блоки пешки, жителей и рейтинга доступны через кнопку «Статистика» слева от «Меню». Статистика закрывается повторным нажатием, кликом вне панели или Escape; игровая клавиатура при открытой статистике заблокирована. Подсказки и кнопка переведены на RU/EN.


## Десктопная панель и пинг
При ширине окна от 801 px боковая панель занимает всю доступную высоту: палитра сверху, постоянно открытая статистика снизу. Экранные стрелки и кнопка выпадающей статистики скрыты. На меньших экранах сохранены палитра и стрелки в двух колонках, статистика открывается по кнопке. При изменении ширины используется один и тот же блок статистики без дублирования данных.
Строка «На связи» показывает время полного ответа запросов состояния/входа в миллисекундах (HTTP round trip, включая чтение JSON), а не ICMP-пинг. Значение обновляется при опросе мира; при ошибке связи и устаревании измерения скрывается. RU/EN единицы следуют языку платформы.


## Работа при высоком пинге (протокол 2)

Своя пешка двигается и рисует локально сразу, без ожидания отдельного ответа. Клиент хранит подтверждённый мир и до 12 ожидающих команд, повторно применяя их после каждого подтверждения сервера. При столкновении или изменении заборов серверный результат исправляет предсказание. Бомбы и установка/снятие заборов подтверждаются сервером; частицы обычной покраски видны сразу. При заполнении очереди ввод ограничивается, чтобы после обрыва пешка не выполняла длинный маршрут сама. Движение остаётся строго по одной клетке, максимум одно игровое действие на серверный тик 120 мс.

Команды отправляются пакетами в POST /api/commands с порядковыми номерами. Сервер ставит их в ограниченную очередь и возвращает результат каждой команды; повторная отправка уже принятого номера не выполняет действие второй раз. Тайм-аут запроса — 8 секунд. Между шагами нет прежнего ожидания ответа и дополнительной задержки 115 мс.

Постоянный POST-поток SSE /api/presence передаёт изменения клеток, пешек, бомб и областей, а также подтверждения. Используется уже поддерживаемый поток SUPER CUBE, без WebSocket и внешних зависимостей. Журнал содержит последние 256 обновлений; полное поле передаётся при входе, пропуске истории, смене серверного процесса или слишком большом накопившемся обновлении. При недоступном потоке клиент переходит на адаптивное HTTP-восстановление по номеру кадра. Зрители используют отдельный поток /api/watch-stream и не занимают пешку.

Движение остальных пешек плавно интерполируется от уже показанной позиции. Повторные эффекты покраски своего игрока подавляются по номеру команды. При обычном закрытии потока пешка сразу становится ботом; резервный тайм-аут при потере сети — 10 секунд плюс серверный тик. Команды старой сессии не переносятся в новую. API прежней версии сохранён для совместимости, но новый клиент использует пакетный протокол.

### Лимит ограждений

Каждая пешка может защитить суммарно **256 клеток** в нескольких непересекающихся прямоугольниках. При загрузке старого мира области сохраняются в порядке записи, пока есть лимит. Превышающая лимит область обрезается по строкам сверху вниз и слева направо (при необходимости на два прямоугольника); лишние клетки освобождаются, их цвета остаются. На восемь пешек приходится максимум 2048 защищённых клеток. Игровой файл мира при подготовке обновления не изменяется — перенос произойдёт при следующем запуске сервера.

Проверки задержек выполняются в изолированных процессах и моделях клиента. Реальные браузеры с ограничением сети, мобильные устройства и production-прокси требуют отдельного прогона. Прокси должен пропускать поток без буферизации (X-Accel-Buffering: no и heartbeat предусмотрены).
